# Адаптивность: стратегия

**Статус:** черновик подхода, цифры уточняются после аудита мобильного кадра и измерений в Figma.
Вьюпорты: **мобильный** (макет: `mobile / home page`, ширина 393), **десктоп** (макет: `desctop / home page`, кадр 2560, контент в контейнере), **планшет** (макета нет — раскладка выводится, см. ниже).

## Принципы
1. **Mobile-first.** Базовые стили — мобильные, на больших экранах добавляем через min-width (Tailwind `tablet:`, `desktop:`).
2. **Один компонент на блок.** Раскладка меняется классами, а не дублированием `HeroMobile` / `HeroDesktop`. Отдельный подкомпонент допустим, только если структура принципиально разная (бургер-меню вместо горизонтального; карусель вместо сетки). Переключение — CSS (варианты `max-desktop:hidden` / `desktop:hidden`; голый `hidden` проигрывает базовому `display` компонента, см. lessons.md), JS только для интерактива.
3. **Имена те же.** Элемент называется одинаково на всех вьюпортах (см. `naming-spec.md`, раздел 6), поэтому `data-el` и анимации общие.
4. **Токены, а не числа.** Брейкпоинты и размеры — в `@theme`; в компонентах нет магических значений.

## Брейкпоинты (предложение)
| Имя | От | Что показывает |
|---|---|---|
| (база) | 0 | мобильный макет, дизайн-ширина 393; корректно тянется до ~767 |
| `tablet` | 768 px (48rem) | выведенная раскладка |
| `desktop` | 1280 px (80rem) | десктопный макет; ниже/выше 1280 контент в контейнере с max-width по Figma (значение — измерить) |
Кадр 2560 в Figma — широкий экран: контент центрируется, фон и декор продолжаются на всю ширину.

## Типографика
В Figma переменные общие для десктопа и мобильного (режимов нет), различается **выбор текстового стиля**: например, H1 на мобильном — `heading/lg` (32/40), на десктопе — `display/xl` (80/88).
- Вводим **семантические роли** (`hero-title`, `section-title`, `lead`, …), каждая отображается на стиль Figma для каждого вьюпорта: мобильный и десктоп — как в макете, планшет — ближайшая ступень шкалы между ними.
- По умолчанию размеры меняются ступенчато на брейкпоинтах (как в макете, проверяемо). Плавное `clamp()` — только для крупных display-заголовков и только по согласованию.

## Планшет (в макете нет)
Правила вывода: узкие сетки десктопа сжимаем (4 колонки → 2, 3 → 2); мобильные одноколоночные блоки растягиваем с боковыми отступами и ограничением ширины текста; навигация — по макету мобильного или десктопного в зависимости от того, помещается ли меню. По каждому блоку фиксируем решение в `docs/blocks/<block>.md` (раздел «Планшет») и показываем пользователю скриншоты на 768 и 1024 px до закрытия блока.

## Изображения и медиа
SVG для векторов и иконок; растровые — экспорт @1x/@2x, `srcset` / `<picture>` там, где мобильная версия отличается кадрированием; ленивая загрузка ниже первого экрана.

## Анимации
Спек анимации блока (`<block>.motion.md`) содержит колонку «вьюпорт»: что отличается на мобильном (упрощение, отсутствие hover). Везде `prefers-reduced-motion`.

## Проверка
Playwright (visual-qa): ширины 393, 768, 1024, 1280, 1440, 2560. Сверка с Figma — на 393 и на десктопной ширине; планшет — скриншоты на согласование.

## Открытые вопросы (ответит аудит мобильного кадра и измерения)
- Max-width контейнера и боковые отступы на десктопе и мобильном.
- Блоки, у которых структура на мобильном другая (меню, ленты, карты, FAQ).
- Как вести себя горизонтальным лентам (логотипы) на узких экранах.
