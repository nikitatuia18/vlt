# Конвенция имён слоёв Figma

**Статус:** принята пользователем. Имена 11 блоков и привязка слагов — на финальной сверке карты переименований.
**Источник правды:** этот файл. Скилл `figma-layer-naming` содержит только процедуру проверки и отсылает сюда.
**Область:** файл Figma `tF23PDdcgeTKK5hsmDZIKg`, кадры `desctop / home page` (`1110:8484`) и `mobile / home page` (`1143:3916`), а также переменные (Variables). Другие страницы и кадры файла не используются.

## 1. Зачем это нужно
Имя слоя — контракт между дизайном, кодом и анимацией:
- из имени блока выводится имя React-компонента и папка (`how-it-works` → `HowItWorks`);
- имя элемента становится якорем в коде (`data-el="hero__title"`) и ключом в `docs/figma-map.json`;
- при анимации слой сопоставляется между кадрами по имени;
- **один и тот же элемент называется одинаково на всех вьюпортах** — так десктоп, планшет и мобильная версия остаются одним компонентом с разной раскладкой, а не тремя копиями.

## 2. Грамматика
```
block      = slug                         hero, next-steps
element    = block "__" part              hero__title
part       = slug [ "-" role ]            hero__cta-primary-label
state      = element "--" slug            faq__item-pricing--open
icon       = "icon-" slug                 icon-arrow-forward
flag       = "icon-flag-" iso2            icon-flag-eu
image      = "img-" slug                  img-logo-visa
slug       = [a-z0-9]+ ( "-" [a-z0-9]+ )* латиница, нижний регистр
```
- Разделители: `__` — блок от элемента, `-` — слова внутри слага, `--` — состояние, `@` — кадр анимации. Других знаков нет: ни пробелов, ни `/`, `—`, `[]`, `()`, `.`, `%`.
- После `__` — не больше **четырёх смысловых частей** (`hero__dash-card-available-label`: мокап, объект, вид, роль). Слаг из нескольких слов — одна часть (`api-keys`). Вне мокапов стремимся к трём. Нужно длиннее — вводим вложенную группу с коротким именем.
- Родитель и ребёнок делят префикс: у группы `hero__dash-card-available` дети — `hero__dash-card-available-label`, `…-number`, `…-bg`.
- Длина имени — до 40 символов.
- Имя описывает **роль**, а не внешний вид: `hero__title`, а не `big-heading`; `features__card-crypto`, а не `card-left`.
- Повторяющиеся элементы различаются **смысловым слагом** по содержимому (`features__card-crypto`, `global__pin-ca`, `header__menu-item-products`). Числовой суффикс (`-1`, `-2`) допустим только когда различия по смыслу нет (одинаковые ячейки таблицы).

## 3. Что именуем и как
| Объект | Шаблон | Пример |
|---|---|---|
| Кадр страницы | `page-{страница}--{вьюпорт}` | `page-home--desktop`, `page-home--mobile` |
| Обёртка страницы | `page-{страница}__body` | `page-home__body` |
| Блок (секция) | `{блок}` | `hero`, `features`, `faq` |
| Контейнер/обёртка внутри блока | `{блок}__{часть}[-wrap]` | `hero__content`, `hero__text-wrap` |
| Текст | `{блок}__{часть}-{роль}` или `{блок}__{роль}` | `hero__title`, `faq__item-pricing-question` |
| Кнопка (пока не компонент) | `{блок}__cta-{primary\|secondary}` + `-label`, `-inner` | `hero__cta-primary-label` |
| Фон блока | `{блок}__bg` | `hero__bg` |
| Декор | `{блок}__deco-{что}` | `faq__deco-corner-tl` |
| Мокап/иллюстрация внутри блока | `{блок}__{мокап}-{часть}[-{роль}]` | `hero__dash-balance-value` |
| Иконка (инстанс или детач) | `icon-{имя в библиотеке}` (Vuesax, kebab-case); смысл иконки даёт родитель | `icon-export`, `icon-arrow-3`, `icon-wallet` |
| Флаг | `icon-flag-{iso2}` | `icon-flag-br` |
| Картинка/логотип бренда | `img-{что}` | `img-logo-visa` |
| Копия для бесшовной ленты | `{имя}-dup{n}` | `logos__item-visa-dup1` |
| Состояние, собранное набором слоёв (переходное) | `{элемент}--{состояние}` | `faq__item-pricing--open` |
| Компонент (когда появятся) | PascalCase | `Button`, `Card` |
| Кадр анимации (будущее) | `{блок}@01-start`, `@02-…`, `@end` | `hero@01-start` |

### Закрытый список ролей текста
`title`, `subtitle`, `eyebrow`, `desc`, `label`, `value`, `number`, `caption`, `link`, `question`, `answer`, `copyright`. Нужна новая роль — предложить и добавить сюда, не изобретать на месте.

### Блоки верхнего уровня
`header`, `hero`, `logos`, `features`, `industries`, `global`, `next-steps`, `faq`, `cta`, `footer`, `footer-bottom`. Один блок = одно уникальное имя на весь файл; реестр — `docs/figma-map.json`.

## 4. Общие правила
- **Запрещены** авто- и импортные имена: `Frame 123`, `Group 5`, `Rectangle 4`, `Ellipse`, `Vector`, `Mask group`, `Union`, `[Copy] …`, имена файлов картинок.
- Переименование меняет **только `name`**: структура, стили, переменные, nodeId не затрагиваются.
- Скрытые слои переименовываются и остаются в макете (решение пользователя); удаление — только по отдельной просьбе.
- **Содержимое векторной графики не именуется.** Внутренности логотипов, иконок, иллюстраций и лоадера (`Vector`, `Union`, `Bounding Box`, `Vector (Stroke)` и т. п.) — единый ассет, в коде он выгружается целиком (SVG/изображение). Именуется сам узел-ассет (`icon-*`, `img-*`, `{блок}__item-*-icon`) и осмысленные обёртки на его уровне, но не каждый путь внутри. Проверка конвенции эти внутренности пропускает.
- Лишние обёртки не удаляются при переименовании: помечаются `…-inner`/`…-wrap` и вносятся в список «кандидаты на упрощение».
- Дубликаты геометрии (`Vector 32–37` и `Flow / …`) не удаляются, помечаются в отчёте.
- Угловые эллипсы 5×5 принадлежат блоку, на чьей границе стоят: `{блок}__deco-corner-{tl|tr|bl|br}`.
- Слои анимации именуются по роли без спецпрефиксов: `global__counter`, `global__counter-digits`, `hero__loader`, `hero__flow-path-{слаг}`.
- Сомнение → знак `?` в карте переименований и вопрос пользователю; решает пользователь.

## 5. Как имя превращается в код
| Figma | Код |
|---|---|
| Блок `how-it-works` | `src/components/blocks/HowItWorks/HowItWorks.tsx` |
| Элемент `hero__title` | `<h1 data-el="hero__title">` (якорь для тестов и анимации; стили — через Tailwind-токены, не по имени) |
| `icon-arrow-forward` | `<Icon name="arrow-forward" />` из `components/ui/` |
| `img-logo-visa` | `src/assets/logos/visa.svg` |
| Состояние `--open` | prop/state `open` компонента |
Имя слоя в коде не меняется и не «переводится»: нашёл слой в Figma — нашёл элемент в коде по тому же имени.

## 6. Адаптивность и имена
- Нужны три вьюпорта: десктоп и мобильный есть в Figma, **планшет в макете отсутствует** — его раскладка выводится из двух соседних вьюпортов (см. `docs/responsive.md`) и согласуется с пользователем. Имена для планшета не создаются.
- Один элемент — одно имя на десктопе и мобильном. Различаются только корневые кадры (`page-home--desktop` / `page-home--mobile`).
- Элемент, существующий только на одном вьюпорте, получает то же имя по общим правилам; факт «только на X» фиксируется в `docs/figma-map.json`, а не в имени.

## 7. Переменные и текстовые стили (Variables)
- Переменные Figma не переименовываются в рамках этапа 1. Нормализация имён для CSS — на этапе 2 (`figma-to-tokens`), по таблице соответствия `docs/tokens-map.md`.
- Найденные проблемы в именах переменных (решение — на этапе 2, с согласия пользователя): опечатки `theme/icon/statiw`, `theme/surface/16 barand`; пробелы `borders & dividers`, `16 black`; регистр `theme/surface/Success`, `Content/primary`; две ветки `theme/icon/*` и `theme/icons/text/*` с одинаковым смыслом; одиночная переменная `Content/primary` вне группы `theme`.

## 8. Чек-лист проверки слоя
1. Имя по грамматике из раздела 2, без запрещённых знаков, ≤ 40 символов.
2. Есть префикс блока (`{блок}__`), кроме `icon-*`, `img-*` и самого блока.
3. Роль, а не вид; текстовая роль из закрытого списка.
4. Нет дубля имени внутри одного родителя.
5. Тот же элемент на другом вьюпорте назван так же.
6. Нет авто- и импортных имён.

## 9. Добавление нового слоя (для дизайнера)
Назвать по таблице раздела 3, проверить по чек-листу, при новой роли или блоке — внести в этот файл и в `docs/figma-map.json`.
