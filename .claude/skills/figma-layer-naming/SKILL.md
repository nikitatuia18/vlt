# Нейминг слоёв Figma — процедура

**Источник правил — `docs/naming-spec.md`. Прочитай его целиком до начала работы.** Здесь только порядок действий; правила не дублируются, чтобы не расходиться.

## Область
Только кадры `desctop / home page` (`1110:8484`) и `mobile / home page` (`1143:3916`) и переменные (Variables) в файле `tF23PDdcgeTKK5hsmDZIKg`. Другие страницы и кадры файла не открывать.

## Аудит
1. Работай точечно, секция за секцией: сначала один `get_metadata` верхнего уровня. Если дети не вернулись — **запрещено перебирать id вслепую**: остановись и попроси пользователя прислать фрагмент (ссылку на выделенный узел или текст). Лимит Figma MCP — 200 вызовов в сутки.
2. Проверяй каждый слой по чек-листу из раздела 8 спеки; авто-имена ловит регулярка `^(Frame|Group|Rectangle|Ellipse|Vector|Line|Polygon|Star|Text|Component|Instance|Mask group|Union|Intersect|Subtract|Exclude)\b.*$` и префикс `[Copy]`.
3. Для каждого нарушения предложи имя по таблице раздела 3 спеки; сомнение помечай `?`.
4. Сопоставляй десктоп и мобильный: один и тот же элемент должен получить одно имя.
5. Отчёт: сводка числами, затем таблица `nodeId | текущее имя | проблема | предложенное имя` по блокам. Однотипные повторы можно группировать.

## Переименование (только после подтверждения карты пользователем)
1. Бэкап страницы, затем переименование пачками по блоку: меняется только `name`.
2. После блока — перечитать дерево и сверить с картой; расхождения перечислить.
3. Повторный аудит: 0 авто-имён и 0 нарушений грамматики; обновить `docs/figma-map.json`.

## Если спека не покрывает случай
Не придумывать: предложить правило, дописать в спеку после согласия пользователя.
