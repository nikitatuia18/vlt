# Тексты сайта Velant Pay

Язык текстов на сайте — **английский (US)**. Отчёты и вопросы пользователю — по-русски.

## 1. Перед написанием: собери голос и факты (не из памяти)
1. Прочитай уже написанные тексты: `src/components/blocks/*/` (файлы с данными `cards.ts`, `items.ts`, `steps.ts`, `brands.ts`, `pins.ts`, а также JSX блоков Hero, Global, NextSteps) и `docs/blocks/*.md`. Тексты из макета — эталон тона; тексты с пометкой «DRAFT»/«черновик» — не эталон.
2. Проверь `docs/naming-spec.md` (имена слоёв) и `docs/lessons.md` (исправленные опечатки).
3. Если пишешь для блока из Figma — текст макета в приоритете. Нужного текста нет — пиши черновик (п. 4), макет не открывай и лимит вызовов Figma не трать.

## 2. Что известно о продукте (опора для текстов; расширять только по подтверждению продукта)
Velant Pay — один API для платежей, крипто, выплат и финансовых операций для компаний, которые двигают деньги через границы. Продукты: Crypto Processing (принять, конвертировать, рассчитаться в крипто), Invoicing (счета в местной валюте, оплата в крипто), Crypto on- и off-ramp (фиат ↔ крипто, курсы от 0.0%), Mass Payouts (автоматические выплаты командам и партнёрам), Banking и Wallet (скоро). Цифры макета: SLA 99.9%, 15+ прямых локальных рельсов, обработка API < 1 секунды. Шаги подключения: демо → KYB → запуск процесса → первая боевая транзакция. Платёжные рельсы по странам — в `pins.ts`.
**Новых фактов не придумывай:** цифры, комиссии, сроки, лицензии, страны, партнёры, названия банков — только из макета и кода. Если нужен факт, которого нет, пиши без него или задай вопрос.

## 3. Голос (выведен из текстов макета)
- **Короткие предложения, глаголы действия, результат первым.** «Accept, convert, and settle crypto payments via a single integration.» «Automate global payouts to teams and partners in a single workflow.»
- **Заголовок:** до ~8 слов; утверждение — предложение с точкой («From first payment to final payout.», «Go global without rebuilding your payments stack.»), вопрос — со знаком вопроса («What are our next steps?»). Без восклицательных знаков и без разговорных «Hey», «Awesome».
- **Описание:** 1–2 короткие фразы, до ~20 слов в предложении, примерно 60–140 знаков. Пара строк в духе карточек отраслей: первая — что делаем, вторая — выгода («Let your clients pay in crypto, and receive fiat. / Forget about chargebacks»).
- **Обращение «you / your».** Мы — «we» (в шагах: «We will show you…»), без «our revolutionary platform».
- **Без рекламных клише:** revolutionary, cutting-edge, best-in-class, game-changing, next-generation. Слово из макета (например «seamlessly» в карточке ramp) можно оставлять, но не размножать.
- **Термины едины:** KYB (капсом), crypto, on-ramp / off-ramp, payouts, rails, E-commerce (с заглавной), API, SLA; названия продуктов — в Title Case как в макете (Crypto Processing, Mass Payouts).
- **Кнопки:** «Book a demo» — единая подпись главного действия; не заменять синонимами.
- **Обещания:** без юридически значимых заявлений (регуляторы, гарантии, «no fees», «no chargebacks», «instant») без подтверждения продукта. Если такая фраза уже есть в макете — оставь, но в отчёте отметь её как «проверить с продуктом».

## 4. Как оформлять результат
1. Тексты кладём в файл данных блока (например `steps.ts`), не в разметку; над списком — комментарий: что из макета, что **DRAFT** (написал разработчик, согласовать с продуктом).
2. В `docs/blocks/<block>.md` — раздел «Тексты (черновик, согласовать с продуктом)» со списком новых текстов.
3. В ответе пользователю: таблица «место (`data-el`) · текст · знаков · статус (макет / черновик)», затем список допущений и вопросов к продукту (одной строкой каждый).
4. Опечатки макета исправляй и сообщай («Pass kyb → Pass KYB»). Тексты макета по смыслу не переписывай без просьбы — предложи вариант отдельной строкой.

## 5. Проверка перед сдачей
- Нет выдуманных цифр, имён и обещаний (п. 2 и 3).
- Длина влезает в макет: заголовок и описание не длиннее аналогов из того же блока больше чем на ~20%; проверь рендер в браузере (`npx playwright test tests/<block>.spec.ts` и скриншот), если менял длинные тексты.
- Орфография и единые термины (п. 3); знаки препинания в конце как у соседних текстов блока.
- Все новые тексты помечены черновиком; финальным текст становится только после слов пользователя.
